# 《冒险者工会：腐化遗物》Godot 开发全案（迭代友好型）

## 一、核心原则
1. 模块化架构：按“核心系统+扩展模块”拆分，模块间低耦合，支持独立迭代；
2. 优先级分层：先落地“能玩通”的最小闭环（MVP），再逐步叠加内容与优化；
3. 迭代友好设计：预留配置文件、接口标准化、数据可视化，降低后续扩展/维护成本；
4. Godot 适配：充分利用引擎特性（如 TileMap、信号系统、资源管理器），提升开发效率。

## 二、开发优先级分层（地基→一层→二层→顶层）

### 阶段一：地基（核心依赖，必须先做，1-2周）
**目标**：搭建底层框架，确保所有系统可扩展、数据可配置，不做具体玩法内容。

#### 1. 项目结构设计（迭代友好核心）
按“功能模块”划分文件夹，统一命名规范（示例如下）：
```
/res
  /config        # 所有可配置数据（JSON格式，无需改代码即可调整）
    - job_config.json  # 职业技能、属性配置
    - item_config.json # 道具、配方配置
    - map_config.json  # 地图区域、地形规则配置
    - enemy_config.json # 怪物、BOSS配置
  /scenes
    /core         # 核心场景（单例，全局复用）
      - GameManager.gd  # 全局状态管理（存档、加载、系统开关）
      - DataManager.gd  # 配置数据加载（读取JSON，提供统一接口）
    /map          # 地图相关场景
    /battle       # 战斗相关场景
    /ui           # UI相关场景
    /character    # 角色相关场景
  /scripts
    /utils        # 工具脚本（通用函数，如数值计算、信号分发）
    /interfaces   # 标准化接口（如 I_Interact.gd、I_Fight.gd，确保模块兼容）
```
- 核心要求：所有数值、规则（如职业技能效果、地形负面、克制倍率）均写在 JSON 配置文件，代码仅负责“读取配置+执行逻辑”，迭代时无需改代码，直接改配置。

#### 2. 核心单例开发
- GameManager：管理全局状态（当前区域、队伍信息、已解锁功能），提供存档/加载接口（用 Godot 的 ResourceSaver / ResourceLoader，支持 JSON 存档，方便调试）；
- DataManager：统一加载所有配置文件，提供 get_job_config(job_id)、get_item_config(item_id) 等接口，其他脚本通过该单例获取数据，避免直接读取文件，降低耦合。

#### 3. 标准化接口定义（迭代友好关键）
定义通用接口脚本（仅含函数声明，无实现），所有模块按接口开发，后续扩展时无需修改原有代码：
- I_Interact.gd：所有可交互对象（采集点、宝箱、石碑）需实现 _interact(character) 函数；
- I_Fight.gd：所有可战斗单位（角色、怪物、BOSS）需实现 get_attack_value()、take_damage(value) 函数；
- I_JobSkill.gd：所有职业技能需实现 _cast(owner, target) 函数（owner 为技能释放者，target 为目标）。

### 阶段二：一层（MVP 核心玩法，能玩通“探索→战斗→养成”闭环，2-3周）
**目标**：落地最小可行版本，仅保留基础职业、核心地图、简化战斗，验证核心玩法。

#### 1. 地图系统（基础版）
- 核心功能：TileMap 网格地图加载（读取 map_config.json 中的区域配置）、体力消耗逻辑、基础地形交互；
- 开发内容：
  - 地图编辑器配置：用 Godot 的 TileMap 绘制 1 个新手区域（森林外围），标记普通地形、沼泽地形、采集点、宝箱格；
  - 移动与体力：角色每移动 1 格触发 GameManager 扣体力，体力耗尽时触发战斗伤害-10% 的负面（读取 map_config.json 中的体力规则）；
  - 交互逻辑：实现 I_Interact.gd 接口，采集点、宝箱触发对应逻辑（商人采集额外获素材，读取 job_config.json 中商人被动效果）。

#### 2. 角色与职业系统（基础版）
- 核心功能：3个基础职业（盗贼、哨兵、商人）的技能触发、属性计算；
- 开发内容：
  - 角色预制体：包含 Character.gd 脚本（实现 I_Fight.gd 接口），属性从 job_config.json 读取（如盗贼初始攻击力=10，每级+2）；
  - 技能系统：实现 I_JobSkill.gd 接口，技能效果按配置执行（如哨兵「侦察」技能，读取配置中“显示怪物等级”的逻辑，无需硬编码）；
  - 队伍管理：支持最多 4 人组队，保存队伍信息到 GameManager，战斗时直接读取。

#### 3. 战斗系统（简化版）
- 核心功能：明雷遇敌、回合制流程、基础克制关系，无复杂特效；
- 开发内容：
  - 遇敌逻辑：地图上的怪物图标（用 Area2D 检测），玩家靠近触发战斗场景切换；
  - 回合流程：按 enemy_config.json 中的速度属性排序，实现“选中角色→选择操作→执行”的基础流程，技能无消耗，道具仅保留“体力药水”；
  - 克制计算：读取 enemy_config.json 中的怪物属性（物理/魔法/防御），按 1.5 倍伤害计算（配置中可改倍率），哨兵「侦察」技能显示怪物属性。

#### 4. 资源与合成系统（基础版）
- 核心功能：2类资源（金币、3种素材）的获取与合成，仅保留 2 个基础配方；
- 开发内容：
  - 资源掉落：战斗胜利后按 enemy_config.json 中的掉落配置发放金币/素材，哨兵被动提升掉落率（读取职业配置）；
  - 合成逻辑：读取 item_config.json 中的配方配置（如“草木素材×3+怪物素材×1=净化草药”），玩家集齐素材后可合成，合成结果实时更新到背包。

### 阶段三：二层（内容填充与功能优化，3-4周）
**目标**：扩充内容、优化体验，新增进阶职业、道具、BOSS，完善系统细节。

#### 1. 内容填充
- 地图：新增山地、沼泽区域（按 map_config.json 配置地形规则），解锁区域传送功能（工会枢纽→各区域）；
- 职业：解锁刺客、元素师2个进阶职业（配置 job_config.json 中的技能与属性，复用现有角色脚本，无需改核心逻辑）；
- 道具：新增诅咒类/功能类道具（共10个以内，配置 item_config.json 中的效果与代价，复用 I_Interact.gd/I_Fight.gd 接口）；
- 配方石板：实现隐藏石板获取逻辑（地图隐藏格触发，读取配置解锁配方），扩充配方到9个。

#### 2. 功能优化
- 战斗系统：新增自动战斗、BOSS 阶段机制（读取 enemy_config.json 中的阶段配置，如血量50%后伤害+20%）；
- UI 优化：新增背包分类、技能快捷栏、势力任务面板，所有 UI 数据从 DataManager 读取，支持动态更新；
- 存档优化：支持多存档位，自动存档（战斗胜利、区域解锁时），手动存档（工会 NPC 交互）。

#### 3. 势力与委托系统
- 核心功能：3个势力的任务发布、声望升级、奖励发放；
- 开发内容：读取 map_config.json 中的势力配置，委托任务按“收集/狩猎/探索”类型随机刷新，完成后提升势力等级，解锁 BOSS 区域与专属道具。

### 阶段四：顶层（主线闭环与迭代优化，2-3周）
**目标**：完成主线 BOSS、结局，优化数值平衡，修复 Bug，支持后续扩展。

#### 1. 主线与 BOSS 系统
- 开发内容：解锁终极区域（腐化神殿），实现终极 BOSS 的属性循环机制（读取 enemy_config.json 中的属性切换规则）；
- 结局触发：击败终极 BOSS 后触发简单结局动画，保存通关状态到 GameManager。

#### 2. 数值平衡迭代
- 基于测试反馈，调整配置文件中的数值（如角色每级属性提升、BOSS 血量/伤害、素材掉落率），无需改代码；
- 优化体验：如体力上限调整、委托任务难度降低、道具效果平衡（如狼化牙加成从50%改为30%）。

#### 3. 扩展预留与维护优化
- 预留新内容接口：如新增职业时，只需在 job_config.json 中添加配置，复用现有角色脚本；新增区域时，只需绘制 TileMap 并配置 map_config.json；
- 调试工具：新增 DebugPanel.gd（仅开发模式显示），支持快速修改数值、解锁功能、传送区域，方便后续迭代测试；
- 代码注释与文档：为核心脚本、接口添加注释，整理配置文件说明文档（如 item_config.json 中每个字段的含义），降低维护成本。

## 三、迭代友好型开发建议（关键）

### 1. 所有规则“配置化”，拒绝硬编码
示例：job_config.json 中盗贼技能配置（后续迭代可直接修改效果/数值）：
```json
{
  "job_id": 1,
  "name": "盗贼",
  "base_attr": {"attack": 10, "defense": 5, "speed": 8},
  "level_up_attr": {"attack": 2, "defense": 1, "speed": 1},
  "skills": [
    {
      "skill_id": 101,
      "name": "突围",
      "type": "passive",
      "effect": "escape_rate+30%",
      "unlock_level": 1
    },
    {
      "skill_id": 102,
      "name": "潜行",
      "type": "active",
      "effect": "avoid_weak_enemy",
      "unlock_level": 5
    }
  ]
}
```
- 好处：迭代时无需修改 Character.gd 或 Skill.gd，直接改 JSON 即可调整技能效果、解锁等级，效率极高。

### 2. 模块间用“信号”通信，避免直接依赖
- 例如：角色体力耗尽时，Character.gd 发送信号「体力耗尽」，GameManager.gd 监听该信号并触发“战斗伤害-10%”的负面，而非 Character.gd 直接调用 GameManager 的函数；
- 好处：后续迭代时，若需修改体力耗尽的效果（如改为“无法移动”），只需修改 GameManager 的信号处理逻辑，不影响 Character.gd 代码。

### 3. 优先实现“通用逻辑”，再做“特殊效果”
- 例如：战斗系统先实现“普攻、技能、道具”的通用流程，再为 BOSS 新增“阶段切换”的特殊逻辑（通过配置 is_boss: true 和 stage_config 区分，复用通用战斗流程）；
- 好处：新增 BOSS 时无需重构战斗系统，仅需添加配置，降低扩展成本。

### 4. 定期备份与版本管理
- 使用 Git 进行版本控制，每完成一个阶段（如地基、MVP）提交一次，迭代时若出现问题可快速回滚；
- 配置文件单独备份，每次迭代前复制一份，避免误改后无法恢复。
